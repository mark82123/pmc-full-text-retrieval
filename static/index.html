PMC Full-Text Retrieval Tool

Biomedical Information Retrieval · Project #1 · PubMed Central XML corpus

Try: cancer immunotherapy "gut microbiome" covid AND vaccine NOT pregnancy alzheimer OR crispr immun* title:diabetes

Fetch from PubMed / PMC by ID

Paste PMIDs or PMC IDs, one per line (commas, PMID: prefixes and PubMed / PMC URLs are fine too). PMIDs are converted with the NCBI ID Converter, the JATS XML is downloaded with E-utilities efetch, parsed, indexed immediately and saved to data/. Only open-access articles have full text in PMC; for the others the PubMed record (title + abstract) is fetched and indexed instead, so abstract retrieval always works.

Add PMC XML documents to the index

Select one or more PubMed Central XML files (.xml / .nxml, JATS format, e.g. downloaded from pmc.ncbi.nlm.nih.gov or via E-utilities efetch.fcgi?db=pmc&id=PMC7536103&retmode=xml). They are parsed, tokenised, stemmed and added to the inverted index immediately; a copy is stored in the data/ directory.

1. 斷詞 Tokenization 與小寫化 Case folding

      
規則只有一條：連續的字母或數字是一個 token，其餘字元（連字號、撇號、括號、標點）都是分隔符，接著全部轉小寫。
        這讓 T-cell、T cell 都能互相匹配，但也有代價——下面的反例都是這個系統真實的行為：

      

        
US、WHO、IT小寫後變成 us、who、it，正好是停用詞而被整個丟掉。查 "WHO guidelines" 只剩 guidelines。

        
AIDS / aids都變成詞幹 aid，疾病名和「幫助」混在一起（同形異義）。

        
SARS → sars → sarPorter 步驟 1a 把結尾的 s 當複數去掉。查 sars 沒問題（查詢詞也走同一條路），但萬用字元 sars* 比對的是索引裡的詞幹 sar，會失敗。

        
1,024、p<0.05逗號與小數點切開數字：1、024、0、05。

        
IL-6 / IL6前者切成 il、6，後者是單一 token il6，兩種寫法對不上（除非用片語 "IL 6"）。

      

      

        
        
      

      

    


    

      
2. 停用詞 Stop words：Snowball 經典清單 + 生醫補充

      
經典清單有兩個常見來源：SMART 系統（Salton, 1971）的 571 字清單，以及 Snowball 詞幹器專案附帶的 174 字英文清單（NLTK 內建的就是這份）。
        本系統採用較保守的 Snowball 清單，再加上 17 個生醫論文高頻、但沒有鑑別力的詞（候選字以語料的 document frequency 掃描，只保留沒有主題意義的語氣詞與連接詞）。停用詞被移除後位置編號仍保留，所以片語 "role of the gut" 仍能以 role 與 gut 相距 3 個位置來比對。

      

      

        
Snowball 英文停用詞 本系統使用

        
生醫論文補充 本系統使用

          
為什麼加這些：et、al 來自 et al.，每篇論文出現數十次；may、might、however、therefore、thus、furthermore 是學術寫作的語氣詞與連接詞，幾乎每篇都出現。曾列入的 us 與 shall 因語料中幾乎不出現、且 us 會誤傷 U.S. 而移除。

      

      
SMART 系統停用詞（Salton, 1971） 僅供比較，本系統未使用 

      

      

    


    

      
3. Porter 詞幹演算法（1980）：五個步驟

      
核心概念是 measure m：把字寫成 [C](VC)m[V] 的形式，m 是「母音串接子音串」的次數，例如 m(tr)=0、m(trouble)=1、m(troubles)=2。每條規則都要求去掉字尾後剩餘部分的 m 夠大，避免把短字砍壞（rate 不會變 rat）。

      

        
步驟規則例子

        
1a複數：sses→ss、ies→i、s→(去掉)；ss 不動patients→patient、therapies→therapi、class→class

        
1b去 -ed / -ing（剩餘部分須含母音），再修補結尾：at/bl/iz 補 e、雙子音變單、cvc 補 egeneralized→generalize、hopping→hop、filing→file

        
1c結尾 y→i（剩餘部分含母音）therapy→therapi、happy→happi

        
2m>0 時長字尾對應：ational→ate、ization→ize、iveness→ive、biliti→ble …organization→organize、sensitiviti→sensitive

        
3m>0 時：icate→ic、ative→(去)、alize→al、ical→ic、ful / ness→(去)generalize→general、analytical→analytic

        
4m>1 時直接砍字尾：ement、ance、ence、able、ment、ant、ent、ism、ate、iti、ous、ive、ize、ion(前面須為 s/t)、al、er、ic、ougeneral→gener、organize→organ、adjustment→adjust

        
5a / 5b去掉結尾 e（m>1，或 m=1 且非 cvc）；ll→l（m>1）activate→activ、controll→control

4. 實作來源：現成函式庫 vs 從零實作

      

        
本專案ir/porter.py 依 Porter 1980 論文的五步驟描述自行實作，ir/stopwords.py 為手動整理的清單，ir/tokenizer.py 為正規表達式斷詞。整個專案只用 Python 標準庫，沒有 import 任何第三方套件；單元測試以 Porter 論文附的範例驗證輸出。

        
NLTKnltk.stem.PorterStemmer（含 Porter 原版與 NLTK 修訂版）、nltk.stem.SnowballStemmer("english")（Porter2，較新的改良版）、nltk.corpus.stopwords（即 Snowball 174 字清單）。

        
snowballstemmer / PyStemmerSnowball 官方的 C 實作與 Python 綁定，支援 20 多種語言，速度最快。

        
scikit-learnsklearn.feature_extraction.text.ENGLISH_STOP_WORDS（318 字，源自 Glasgow IR 清單）；TfidfVectorizer 可直接做 TF-IDF，但不含詞幹化。

        
spaCy / Stanza不做詞幹化而做 lemmatization（查字典還原原形：mice→mouse、analyses→analysis），需要詞性標注模型，能修正上面大部分反例，但無法用純標準庫實作。

查詢語法

      

        
cancer immunotherapy一般關鍵字，以「預設運算子」組合：AND 表示每個詞都要出現，OR 表示任一個詞出現即可

        
covid AND vaccine NOT pregnancyBoolean 運算子ⓘ（AND、OR、NOT、-term），可加括號；優先順序ⓘ 為 NOT > AND > OR

        
"gut microbiome"Phrase queryⓘ，使用 positional indexⓘ 比對；片語中的 stop wordⓘ 會被跳過但保留位置間距，例如 "role of the gut" 會比對 role 與 gut 相距 3 個位置

        
immun*Prefix wildcardⓘ，比對所有以 immun 開頭的索引詞

        
title:crispr、abstract:vaccine、body:…Field 限制ⓘ，只在指定欄位中比對

      


      
新增文章

      
在 Add Documents 分頁貼上 PMID 或 PMC ID（每行一個），按 Fetch & index：系統先用 NCBI ID Converter 把 PMID 轉成 PMCID，再用 E-utilities efetch 下載 JATS XML，解析後立即建入索引並存到 data/。只有 open access 文章在 PMC 有全文；沒有全文的 PMID 會改從 PubMed 抓標題與摘要建索引（文件 ID 以 PMID 開頭，狀態表標示 abstract only）。


      
處理流程 (pipeline)

      
    
        
  1. Parsing 解析 – 讀取 JATS XMLⓘ，取出標題、摘要、章節標題、內文段落與 metadata（作者、期刊、年份、關鍵字）。引用標記、表格與參考文獻清單會被移除，避免大量無意義的數字與人名進入索引。
    2. 
        
  2. Tokenization 斷詞ⓘ – 以連續的字母/數字為單位；連字號會切開（COVID-19 → covid、19）。
    3. 
        
  3. Normalization 正規化 – 轉小寫、移除 191 個 stop word、以 Porter stemmingⓘ 取詞幹（自行實作 1980 年的演算法）。
    4. 
        
  4. Indexing 建立索引 – Inverted indexⓘ：term → {doc → [positions]}，並記錄文件長度與各欄位的位置區間。
    5. 
        
  5. Matching 比對 – 對 posting list 做集合運算 (AND/OR/NOT)、以位置差比對片語、展開前綴萬用字元。
    6. 
        
  6. Field scoring 分欄評分 – 每篇命中文件同時計算四個分數：整篇 (all)、title、abstract、body。欄位分數只使用落在該欄位的命中位置，長度正規化也改用該欄位自己的長度與語料中該欄位的平均長度（摘要跟摘要比、內文跟內文比）。Rank by 選單決定用哪個分數排序；選 abstract 時只在摘要有命中的文件才會出現。結果卡右側會並列顯示三個欄位分數。
    7. 
        
  7. Ranking 排序 – Okapi BM25ⓘ（k1 = 1.5、b = 0.75），或 TF-IDFⓘ，或單純命中次數；標題中的命中乘以 1.25 倍加權。
    8. 
        
  8. Presentation 呈現 – 以最相關的句子作為 snippetⓘ、關鍵字反白、命中位置分布圖 (match map)、詞頻圖表與文件統計。
    9. 
      


      
句子偵測 (EOSⓘ) – 規則式方法

      
候選的句子邊界為 . ! ?（或刪節號）加上可有可無的右引號/右括號，之後接空白。符合以下任一情況時不會切句：

      
    
        
  • 下一個字元是小寫字母（句子應以大寫、數字、括號或符號開頭）；
    • 
        
  • 句號前的詞是已知縮寫ⓘ（e.g., i.e., et al., Fig., Dr., vs., approx., No., Ref., Eq., Vol., Jan.…）；
    • 
        
  • 句號前的詞只有一個字母（人名縮寫 J. R. Smith、屬名 E. coli）或是帶點的縮寫（a.m.、U.S.）；
    • 
        
  • 句號夾在數字之間（0.05）— 後面沒有空白，根本不會成為候選。
    • 
      

      
段落結尾與標題一定視為句子結束。介面同時顯示 naive 方法ⓘ（見到 . ! ? 就切）的句數以供比較。


      
統計指標說明

      

        
Characters字元數（含空白）；另有不含空白的版本

        
Tokens / Wordstoken 為字母或數字的連續片段；word 只計純字母的 token（不含 2020、19 這類數字）

        
Unique words轉小寫後不重複的 word 數量

        
Index terms / Unique terms經 stop word 移除與 stemming 後留下的索引詞數量／不重複詞幹數量

        
Sentences規則式 EOS 偵測得到的句數；naive 為基準值

        
Lexical diversity詞彙多樣性ⓘ = unique terms ÷ index terms

        
df / cfdfⓘ = 含此詞的文件數；cfⓘ = 此詞在全語料庫的總出現次數
