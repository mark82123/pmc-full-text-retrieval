科學文獻語料的詞頻分布是否符合 Zipf 定律？

Does the word-frequency distribution of a scientific document collection follow Zipf's Law?

以 1,000 篇 PubMed 摘要（查詢詞 GLP-1）建立語料庫，計算 CF / DF，繪製 rank–frequency 與 log-log 圖、估計 Zipf exponent，比較四種前處理條件，並連結到 CF、DF、IDF 與 Luhn 有效詞的鑑別力。

結論摘要

  • 近似符合。條件 B 下整條曲線的最小平方迴歸得到 k = 1.419、R² = 0.966、RMSE = 0.115（log10 單位）。log-log 圖接近直線但有彎曲：頭部比單一直線平（k = 0.82）、尾部比直線陡（k = 1.60）。

1. 語料與前處理流程

1.1 語料來源

語料透過 PubMed E-utilities（esearch + efetch）下載查詢詞 GLP-1 最新的 1,000 篇英文摘要，每篇以 PMID 為唯一 Document ID，文件內容為 title + abstract。語料存成 data/pubmed_glp1.jsonl（一行一筆），例如 PMID38757954, PMID39421913, PMID39724554, PMID40049721, PMID40358690。主題集中（GLP-1 受體促效劑、肥胖、第二型糖尿病），因此高頻的內容詞會非常明顯，這對觀察 CF 與 DF 的差異很有幫助。

3. Zipf 分布（Part V）

實驗一　Rank 對 frequency

以 condition B 的 13,323 個 term 依 CF 排序。左圖用線性座標：曲線貼著兩軸，幾乎看不出分布；右圖把頻率軸取對數，整條長尾都看得見。這就是 Zipf 分布需要適當 scale 的原因。

4. 必答分析

Q1　你的文件語料是否符合 Zipf 定律？

近似符合，但不是嚴格的單一冪次律。 log-log 圖上 13,323 個點大致落在一條直線附近（R² = 0.966），「少數詞極常見、多數詞極罕見」的長尾形狀非常明確。但曲線有系統性的彎曲：頭部（rank 1–23）在直線下方，平均殘差 -1.04，也就是最高頻的詞比直線預測少一個數量級；尾部則因頻率只能是整數 1、2、3… 而呈階梯狀並向下彎。

Q2　估計出的 Zipf exponent 是多少？

整條曲線 k = 1.419（condition B）。分段估計差異很大：高頻 0.82、中頻 0.86、低頻 1.60。四個條件的整體 k 為 A 1.10、B 1.42、C 1.37、D 1.48。整體 k 偏高（> 1）的原因是 12,762 個低頻詞（佔詞彙 95.8%）在未加權的 OLS 中佔了絕大多數的資料點，把斜率拉向尾部較陡的斜率。

為什麼以條件 B 為準，而不是 C 或 D？　B 是 spec 必做的三個步驟（斷詞、小寫、標點）做完、尚未加入變因（停用詞、stemming）的狀態，term 仍等於「詞」、曲線頭部完整，是檢驗「語料本身符不符合定律」的對象。C、D 是為了檢索而做的處理，動到的正好是定律描述的兩端：

  • C（去停用詞）砍掉的就是曲線的頭部。rank 1–10、佔 26.0% token 的點整段消失，glp、receptor 遞補成 rank 1、2，但彼此的落差遠小於原本的頭部，高頻段 k 由 0.82 降到 0.56，頭部出現「肩膀」，離直線更遠。
  • D（stemming）改變了「詞」的定義。patient + patients、obesity + obese 合併後中高頻的 CF 被加總、尾巴縮短，整體 k 升到 1.48，高頻段 k 只剩 0.48，R²、RMSE 是四者中最差的；此時單位已是詞幹，不再是原本以詞為單位的問題。
  • 若課堂慣例是「跑完整條 pipeline 再估」，可改報 D 的 k = 1.48（或 C 的 1.37），但結論要跟著改為「頭部明顯偏離、擬合較差」。本報告把 B 當基準回答 Q1–Q4，C、D 的變化留在第 5 節說明。

Q3　R² 足以證明分布符合 Zipf 定律嗎？

不夠。理由有三：(1) R² 只量「相對於平均值解釋了多少變異」，在 log-log 空間裡任何單調遞減的長尾（log-normal、stretched exponential、Zipf–Mandelbrot）都能得到 0.95 以上的 R²，它分不出這些模型。(2) 殘差不是隨機散布：三段相對整體迴歸線的平均殘差是 -1.04 / -0.19 / +0.01，而且分段斜率 0.82 / 0.86 / 1.60 彼此差異明顯——系統性的彎曲代表單一冪次律並不完全成立。(3) OLS 把每個 term 當成一個點，等權重地被數量龐大的 hapax（35.3% 的詞）主導，所以 R² 主要反映尾部。要「證明」需要殘差圖、分段斜率、以 MLE 估計 k 並用 KS 檢定或 likelihood ratio 與替代模型比較。

Q4　Rank–frequency 曲線的哪一段最符合 Zipf 定律？

中頻段（rank 24–561，538 個 term、佔 42.3% 的 token）：R² = 0.9975、RMSE = 0.0136，是三段中最直的一段，斜率 0.86 也最接近 k ≈ 1 的理想值。高頻段只有 23 個點且多為功能詞，曲線較平（k = 0.82）；低頻段受整數頻率與 hapax 影響呈階梯狀、斜率最陡（k = 1.60）。

5. 前處理的影響（續）

  1. Zipf exponent　整體 k：A = 1.10、B = 1.42、C = 1.37、D = 1.48。A 最接近 1，是因為黏著標點的詞製造了大量只出現一次的詞型，拉長了尾巴；去標點後尾巴變短、斜率變陡。移除停用詞砍掉曲線最高的頭部，頭段更平（高頻段 k：B = 0.82 → C = 0.56）。Stemming 縮短尾巴並抬高中段，整體 k 上升到 1.48。
  2. 分布的形狀 Shape　四條曲線的中段近乎平行；差異集中在頭部（停用詞移除後變平、出現「肩膀」）與尾部（詞彙越小，曲線越早觸底）。前處理改變的是截距與頭尾，不改變長尾本質。

Q1　為什麼一個詞可以 CF 很高、DF 卻相對低？

因為它是少數文件的「主題詞」：只在少數文件出現，但在那些文件裡反覆出現。semaglutide CF = 791 只分布在 237 篇（每篇 3.3 次）、placebo CF = 251 只在 86 篇（2.9 次）、0 CF = 2,731 只在 414 篇；反之 results、methods、conclusions 每篇出現一次左右（CF / DF ≈ 1.0–1.1），CF 接近 DF。

Q2　哪個量能告訴我們一個詞是否廣泛分布在文件中？

DF（或 DF / N）。CF 只說總量，分不出「100 篇各 1 次」與「1 篇 100 次」：peptide 與 risk 的 CF 幾乎相同（1,078 vs 1,074），但 DF 是 720 vs 424。

Q3　為什麼 CF 與 DF 在資訊檢索中都重要？

DF 決定 IDF（詞的鑑別力）與 posting list 的長度（查詢成本）；CF 決定位置索引的大小與語言模型的 collection probability（平滑用）。兩者的落差（burstiness，CF / DF 遠大於 1）本身就是「內容詞」的訊號。

Zipf 分布告訴我們頻率極度不均：排名最前的少數詞佔了大部分 token（B 的前 10 名佔 18.5%）。若只用 TF 計分，分數會被這些詞主導。IDF 正好以 log 尺度抵銷冪次律的頭部，讓落在中、低頻段的內容詞得到較高權重——TF-IDF 等於是依 Zipf 曲線上的位置重新加權。下一頁用 Luhn 的「有效詞鑑別力」把這件事畫出來。

7.1 Luhn 有效詞的鑑別力（resolving power）

8. 對資訊檢索系統的意義（Part IX）

Why does Zipf's Law matter to an Information Retrieval system?　為什麼 Zipf 定律對資訊檢索系統很重要？（685 字）

Zipf 定律不是關於詞頻的趣聞，而是檢索系統每個元件都必須面對的統計形狀。在這份語料裡，少數幾個詞佔了大部分的文字，而大多數詞只出現一兩次；這種不均衡決定了詞要怎麼被過濾、儲存與加權。

停用詞移除。排名最前的詞幾乎沒有鑑別價值，因為它們出現在幾乎每一篇文件裡。在條件 B，upper cut-off 以上的 9 個詞（and、of、the、in……）佔了全部 token 的 17.5%，卻只貢獻 0.3% 的 CF × IDF 總權重；它們的 DF 是 1,000 篇裡的 925–999 篇。含有 the 的查詢會命中每一篇文件，這個詞無法替任何文件排序，只會增加處理時間。移除 191 個停用詞讓 token 數減少 26%，詞彙卻只少 128 個——這等於事先套用了 Luhn 的 upper cut-off。但片語查詢（例如 "to be or not to be"）需要這些詞，所以現代搜尋引擎多半把停用詞留在索引裡、用權重壓低，而不是直接丟掉。

倒排索引。字典（dictionary）的大小隨詞彙成長，而長尾表示字典被罕見詞主導：35% 的詞是 hapax（只出現一次）。因此字典很大但每個項目都很短，適合 front coding 與分塊儲存。Postings list 則是相反的輪廓：它的長度跟著 DF 分布走，少數幾條極長（and 有 999 筆 posting），絕大多數只有一兩筆。索引的總大小由那幾條長串決定，壓縮的效益也集中在那裡：長串裡相鄰文件 ID 的間距很小，用 variable-byte 或 gamma 編碼只要一兩個 byte。查詢處理同樣利用這種偏斜：先掃短串再與長串做交集，成本最低。

TF-IDF。IDF = log10(N / DF) 直接取決於一個詞在 Zipf 曲線上的位置。and 的 IDF 是 0.0004；semaglutide（DF = 237）是 0.63；retinopathy（DF = 10）是 2.0。這個加權把分布的頭部壓平——否則原始詞頻會主導每一個分數——並抬高 Luhn 所說有效詞所在的中段。我們的鑑別力量測證實了這一點：在條件 C，rank 1–112 的 112 個詞佔 32% 的 token，也有最高的平均 CF × IDF；13,083 個罕見詞單獨看都很弱，但合計仍佔 88% 的權重。這就是為什麼長尾要留在索引裡、交給 IDF 處理，而不是用 lower cut-off 切掉。

總結：Zipf 定律告訴系統設計者資訊在哪裡——不在頭部（那是雜訊），也不在任何單一的尾部詞，而在中間那一段；停用詞表、索引壓縮與 TF-IDF 都是為了把這一段分離出來而設計的。
